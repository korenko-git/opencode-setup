# Database

Use this skill when a task changes schema, queries, migrations, or connection settings.

## Core Rules
- Use `SQLAlchemy` async or another clearly async-first DB layer.
- Manage schema evolution through Alembic migrations.
- Prefer explicit columns over `SELECT *` in production queries.
- Keep data access logic out of route handlers.

## Recommended Backend Layout
```text
backend/
  app/
    db/
      session.py
      models/
      migrations/
    repositories/
```

## Queries
- Use parameterized queries only.
- Select only needed columns.
- Add deterministic ordering to paginated queries.
- Use transactions for multi-step writes.
- Be explicit about isolation/locking for balance deductions, job picking, and idempotent webhooks.

## Indexing Rules
- Index foreign keys used in joins and filters.
- Index unique external IDs such as `transaction_id`, `provider_payment_id`, or `google_id`.
- Add compound indexes for common filter+sort patterns.
- Review query plans for heavy list or aggregation queries.

## Pooling
Document and configure pool settings explicitly:

```env
DB_POOL_SIZE=20
DB_POOL_MAX_OVERFLOW=20
DB_POOL_TIMEOUT=30
```

## Alembic Conventions
- One migration per logical schema change.
- Use descriptive names such as `add_credit_transaction_id_index`.
- Review autogenerated migrations before applying.
- Do not mix schema changes and unrelated data rewrites in one migration unless necessary.

## Safety Rules
- Backfill in controlled steps for large tables.
- Add nullable columns first when zero-downtime matters, then backfill, then enforce constraints.
- Test `upgrade` and `downgrade` paths when practical.

## Checklist
- [ ] Add or update models
- [ ] Create and review Alembic migration
- [ ] Use explicit columns and parameterized queries
- [ ] Add required indexes and constraints
- [ ] Configure connection pool settings
- [ ] Verify transactional correctness for concurrent paths
